# Технічне завдання

**Проект:** Прогноз продажів товарів на тиждень в розрізі SKU
**Виконавець:** Горбунова Крістіна, група УМ-з31
**Курс:** Бізнес-прогнозування
**Дата:** січень 2026

---

## 1. Бізнес-контекст

Торгова мережа працює у категоріях побутової техніки та електроніки. Закупка
товару в умовах нестабільного попиту вимагає тижневого прогнозу продажів
у розрізі **SKU × магазин**, оскільки:

- Замовлення постачальнику формуються щотижня
- Залишки відрізняються по магазинах і по SKU
- Помилка прогнозу веде або до **out-of-stock** (втрачені продажі), або до
  **over-stock** (заморожені оборотні кошти)

Цільова формула планування замовлення:

```
Q = Fct − St − GiT + SS_Fct
```

де `Q` — обсяг замовлення, `Fct` — прогноз продажів на горизонт, `St` —
поточний залишок у магазині, `GiT` — товар у дорозі (Goods in Transit),
`SS_Fct` — страховий запас, який залежить від прогнозу та його довірчого
інтервалу.

## 2. Мета проекту

Побудувати модель машинного навчання, що прогнозує **щотижневий обсяг
продажів** (qty) для кожної пари **(store_id, sku_id)** на горизонт
**4 тижні** наперед з контрольованою точністю (MAPE на тестовому періоді).

## 3. Об'єкт і розріз прогнозування

| Параметр | Значення |
|---|---|
| Гранулярність | SKU × магазин × тиждень |
| Горизонт прогнозу | 4 тижні наперед |
| Глибина історії | 12 місяців (366 днів) |
| К-сть магазинів | 2 (`215`, `312`) |
| К-сть SKU | 15 (у 3 категоріях: Ноутбуки, Смартфони, Холодильники) |
| Цільова змінна | `qty` (кількість одиниць, проданих за тиждень) |

## 4. Джерела даних

Синтетичний датасет [`data/sku_sales_dataset.csv`](../data/sku_sales_dataset.csv)
з полями:

| Поле | Опис |
|---|---|
| `date` | дата продажу (день) |
| `store_id` | ідентифікатор магазину |
| `sku_id` | ідентифікатор SKU |
| `category` | категорія товару |
| `qty` | кількість одиниць, проданих за день |
| `price` | ціна у грн |
| `promo` | прапорець акції (0/1) |

Генератор: [`scripts/generate_dataset.py`](../scripts/generate_dataset.py).
У датасет закладено: тиждень­денну сезонність, річну сезонність по категоріях,
свята (8 березня, 1 травня, 24 серпня, Black Friday, Новий рік), випадкові
акції зі знижкою −10% і підвищеним попитом.

## 5. Підхід до моделювання

**Етап 1 — підготовка ознак:**
- Агрегація денних продажів до тижня (`W-MON`)
- Календарні ознаки: `week_of_year`, `month`, `quarter`, `is_holiday_week`
- Лагові ознаки: `lag_1`, `lag_2`, `lag_4`, `lag_12` (тижнів)
- Ковзні середні: `rolling_mean_4`, `rolling_mean_12`
- Промо-частка тижня, середня ціна тижня

**Етап 2 — baseline:** наївний прогноз = середнє за останні 4 тижні.

**Етап 3 — основна модель:** **LightGBM** (gradient boosting) на flat-таблиці
(SKU, store) + календарні ознаки + лаги.

**Етап 4 — train/test split:**
- Train: тижні 1–44 (2024-01-01 ... 2024-10-27)
- Test: тижні 45–52 (останні 8 тижнів) — walk-forward

## 6. Метрики оцінки

| Метрика | Формула | Поріг прийнятності |
|---|---|---|
| **MAPE** | `mean(|y − ŷ| / y)` | ≤ 25% |
| **WAPE** | `sum(|y − ŷ|) / sum(y)` | ≤ 20% |
| **MAE** | `mean(|y − ŷ|)` | відносний показник |
| **RMSE** | `sqrt(mean((y − ŷ)²))` | відносний показник |
| **Bias** | `mean(ŷ − y) / mean(y)` | у межах ±5% |

Основна — **WAPE** (стійка до нулів у деяких SKU-тижнях, на відміну від MAPE).

## 8. Ризики та припущення

- **Холодний старт нового SKU:** для SKU без історії модель не дасть
  адекватного прогнозу — потрібен fallback на категорійне середнє.
- **Зміна цінової політики / акцій:** якщо в майбутньому промо-стратегія
  суттєво зміниться, точність впаде. Потрібна періодична переоцінка моделі
  (раз на квартал).
- **Свята-аномалії:** Black Friday/Новий рік дають викиди — обробляються
  через `is_holiday_week`.
